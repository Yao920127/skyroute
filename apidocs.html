Duffel Flights API 使用指南

整理自 Duffel 官方 18 篇 Flights 指南：搜尋、訂位、加購、訂位後管理。所有呼叫範例皆使用 Python 的 requests。

① 搜尋 → 訂位offer request → offer → order ② 加購行李、選位、準確價格、保留訂位 ③ 訂位後取消、改票、補買行李

環境與共用 helper

  1. 註冊 Duffel 帳號（約 1 分鐘）。
  2. 在 Dashboard 導覽列點 More → Developers，到 Access tokens 建立測試用 access token。
  3. 把 token 放進環境變數，不要寫死在程式碼或提交到版本控制。
shell
# 安裝
pip install requests

# 設定 token（請換成你自己的）
export DUFFEL_ACCESS_TOKEN="你的測試 token"

每個請求都需要這幾個標頭：Authorization: Bearer …、Duffel-Version: v2、Accept: application/json，有 body 時再加 Content-Type: application/json。請求的 body 一律包在 {"data": …} 裡，回應內容也在 data 裡。下面這個 helper 會處理這些事，後面所有範例都假設你已經定義了它。

duffel_client.py
import os
import requests

BASE_URL = "https://api.duffel.com"
HEADERS = {
    "Accept": "application/json",
    "Content-Type": "application/json",
    "Duffel-Version": "v2",
    "Authorization": f"Bearer {os.environ['DUFFEL_ACCESS_TOKEN']}",
}


class DuffelError(Exception):
    """API 回傳非 2xx 時拋出，帶有狀態碼與 errors 內容。"""

    def __init__(self, status, errors):
        super().__init__(f"HTTP {status}: {errors}")
        self.status = status
        self.errors = errors


def duffel(method, path, *, params=None, data=None):
    """呼叫 Duffel API，回傳回應中的 `data`。"""
    resp = requests.request(
        method,
        BASE_URL + path,
        headers=HEADERS,
        params=params,
        json={"data": data} if data is not None else None,
        timeout=60,
    )
    body = resp.json() if resp.content else {}
    if not resp.ok:
        raise DuffelError(resp.status_code, body.get("errors", body))
    return body.get("data")
提示範例中的 requests 會自動處理 gzip，不需要手動加 Accept-Encoding。若想一併使用 Duffel 官方 JavaScript 客戶端，可參考官方文件；本頁僅示範 Python 直接呼叫 REST。

快速開始：搜尋 → 訂位 Getting Started

情境：Tony、Pepper 與女兒 Morgan（1 歲）要從紐約飛亞特蘭大，6/11 出發、6/18 回程，想坐商務艙。流程分三步：

  1. 搜尋航班：建立 offer request，取得 offers。
  2. 選擇 offer：重新取得最新版 offer（offer 很快就會過期）。
  3. 建立訂單：帶上 offer ID、乘客資料、付款。

1. 搜尋航班

python
offer_request = duffel(
    "POST",
    "/air/offer_requests",
    params={"return_offers": "true"},
    data={
        "slices": [
            {"origin": "NYC", "destination": "ATL", "departure_date": "2026-06-11"},
            {"origin": "ATL", "destination": "NYC", "departure_date": "2026-06-18"},
        ],
        # 18 歲以下必須提供 age；成人只需 type
        "passengers": [{"type": "adult"}, {"type": "adult"}, {"age": 1}],
        "cabin_class": "business",
    },
)

offers = offer_request["offers"]
passenger_ids = [p["id"] for p in offer_request["passengers"]]  # 訂位時要用
  • slice：一段「出發地→目的地＋日期」的旅程。地點可用機場 IATA 碼（ATL）或城市碼（NYC，涵蓋多個機場）。
  • 乘客：成人用 {"type": "adult"}；未滿 18 歲請給 age，因為航空公司依年齡定價。
  • 回應會回傳 offer request 的 id（之後可再 取回）、offers，以及每位乘客自動產生的 id。

取得 offers 有兩種方式：

  1. 一次回傳全部（上面的做法）：適合應用程式先處理過資料再顯示。
  2. 串流分批（POST /air/batch_offer_requests）：適合想「一有結果就先顯示」的畫面。

2. 選擇 offer：取得最新版

python
offer = duffel("GET", f"/air/offers/{offer_id}")

total_amount = offer["total_amount"]      # 例如 "7477.00"
total_currency = offer["total_currency"]  # 例如 "GBP"

請在使用者選好 offer、還沒要他填完整乘客資料與付款之前做這件事，價格才是最新的。每個 offer 內含 slices，每個 slice 又含一個或多個 segments（實際航班，含航空公司、班號、行李額度）。例如 JFK→IAD→ATL 的去程就有 2 個 segment；直飛的回程只有 1 個。

3. 建立訂單

你需要：offer ID、乘客資料、付款資訊。請先自行向客戶收款，再建立訂單。付款 type 有兩種：

  • arc_bsp_cash：你是 IATA 註冊旅行社，使用自己與航空公司的關係。
  • balance：使用 Duffel 託管內容（Managed Content），從 Duffel 餘額扣款。若想直接向客戶刷卡，見官方「Paying with customer cards」指南。
python
adult_1, adult_2, infant = passenger_ids

order = duffel(

    "/air/orders",
    data={

            {
                "type": "balance",
                "currency": total_currency,        # ISO 4217，須與 offer 的 total_currency 相同
                "amount": total_amount,            # 須與 offer 的 total_amount 相同
            }
        ],
        "passengers": [
            {
                "id": adult_1,
                "title": "mr", "gender": "m",
                "given_name": "Tony", "family_name": "Stark",
                "born_on": "1980-07-24",
                "email": "tony@example.com", "phone_number": "+442080160508",
                "infant_passenger_id": infant,     # 嬰兒（0–1 歲）要指定負責的成人
            },
            {
                "id": adult_2,
                "title": "mrs", "gender": "f",
                "given_name": "Pepper", "family_name": "Potts",
                "born_on": "1983-11-02",
                "email": "potts@example.com", "phone_number": "+442080160509",
            },
            {
                "id": infant,
                "title": "mrs", "gender": "f",
                "given_name": "Morgan", "family_name": "Stark",
                "born_on": "2019-08-24",
                "email": "morgan@example.com", "phone_number": "+442080160506",
            },
        ],
    },
)

print(order["id"], order["booking_reference"])  # 航空公司訂位代號
注意
  • 乘客的 id 要用搜尋結果裡該乘客的 ID。
  • 務必填乘客本人的 email，且報到應由乘客本人完成。
  • 每位嬰兒都必須指派一位「唯一」的負責成人（infant_passenger_id，不可重複）。
  • 訂位流程與訂位後，必須顯示 Duffel 規定的法律告知，讓客戶了解資料用途與適用規則。

搜尋最佳實務 Search

熱門航線的 offers 可高達數萬筆（例如 JFK↔MAD：30 個去程 × 20 個回程 = 600 種組合，每種再有 5 個票價品牌可混搭，共約 15,000 筆）。善用過濾條件可以縮小 payload 並加快速度。官方建議盡量使用這些條件，必要時設為預設值。

過濾條件（放在 request body）

欄位效果建議
cabin_class艙等會直接傳給各航空公司，結果更相關也更快。讓使用者選艙等時一定要帶。
max_connections只回傳轉機次數不超過此值的 offers。設 0 或 1 在相關性與速度間最平衡；2 會有更多選項。未指定時 Duffel 預設最多 1 次轉機。
departure_time / arrival_time（放在 slice 內）限制起飛／抵達的時段（from、to，格式 HH:MM）。使用者已知要搭哪班時，這是最快的搜尋方式。
python
offer_request = duffel(
    "POST",
    "/air/offer_requests",
    params={"return_offers": "true", "supplier_timeout": 10000},  # 毫秒
    data={
        "slices": [
            {
                "origin": "MAD",
                "destination": "JFK",
                "departure_date": "2026-12-05",
                "departure_time": {"from": "08:00", "to": "11:00"},
                "arrival_time": {"from": "09:45", "to": "17:00"},
            },
            {"origin": "JFK", "destination": "MAD", "departure_date": "2026-12-10"},
        ],
        "passengers": [{"type": "adult"}],
        "cabin_class": "first",
        "max_connections": 0,
    },
)

查詢參數：supplier_timeout

控制「使用者要等多久」。數值小 → 偏重速度、結果較少；數值大 → 選項較多。未指定時預設 20 秒（官方也建議用這個值）。上面範例用 10000（毫秒）。

來源：Following Search Best Practices。延伸閱讀：Duffel 部落格「Designing the Modern Flight Booking Experience」、「Why Your Customers Will Thank You For NDC」。

回應格式選擇 Search

搜尋時用查詢參數 view 決定 offers 的結構：

值結構適用
offers（預設）扁平的 offers 陣列，每筆都內嵌完整的 slice／segment／航空公司／機場資料。把每個 offer 當作獨立單位、不需依行程分組的整合。
itinerariesslices[] → itineraries[] → brands[] → offers[]；航空公司、地點、機型抽到頂層 references 對照表。想依行程＋票價品牌分組顯示、想要更小的 payload、或要提供分開購票。

三個端點都支援 view：POST /air/offer_requests、GET /air/offer_requests/:id、GET /air/batch_offer_requests/:id。省略時預設為 offers，既有整合不受影響。Accept 標頭仍只決定傳輸編碼，view 只影響 JSON 內部結構。

python
result = duffel(
    "POST",
    "/air/offer_requests",
    params={"view": "itineraries"},
    data={
        "cabin_class": "economy",
        "passengers": [{"type": "adult"}],
        "slices": [
            {"origin": "NYC", "destination": "LON", "departure_date": "2026-12-15"},
            {"origin": "LON", "destination": "NYC", "departure_date": "2026-12-20"},
        ],
    },
)

airlines = result["references"]["airlines"]  # 以 ID 查表
for slice_ in result["slices"]:
    for itinerary in slice_["itineraries"]:
        for brand in itinerary["brands"]:
            for offer in brand["offers"]:
                owner = airlines[offer["owner"]]["name"]
                print(owner, brand["fare_brand_name"],
                      offer["total_amount"], offer["total_currency"], offer["type"])

分開購票行程 Search

分開購票（split-ticket）是把多段行程拆成各自獨立的單程 offer（常來自不同航空公司）來組合，選擇更多、有時更便宜。

需要先開通此功能需聯絡 Duffel 支援（help@duffel.com）開啟；且只會出現在 view=itineraries 的回應中，不會出現在預設的扁平 offers 回應。

請求

  1. body 設 include_split_ticket: true。
  2. 查詢參數加上 view=itineraries。

include_split_ticket 對單程（單一 slice）搜尋無效。

python
result = duffel(
    "POST",
    "/air/offer_requests",
    params={"view": "itineraries"},
    data={
        "include_split_ticket": True,
        "cabin_class": "economy",
        "passengers": [{"type": "adult"}],
        "slices": [
            {"origin": "NYC", "destination": "LON", "departure_date": "2026-12-15"},
            {"origin": "LON", "destination": "NYC", "departure_date": "2026-12-20"},
        ],
    },
)

回應與組合

  • type: "single_ticket"：一家航空公司涵蓋全部 slice，照一般方式訂。
  • type: "split_ticket"：單一 slice 的單程 offer，每個 slice 各自回傳。

組合方式：每個 slice 各挑一個 split_ticket offer。single_ticket 自己就涵蓋整趟行程，兩者擇一，不可混用。

計價與訂位：一個 offer 一張訂單

python
chosen = ["off_B", "off_C"]  # 客人在 slice 0 與 slice 1 各選的 split_ticket offer

# 1) 各自取得最新價格
latest = [duffel("GET", f"/air/offers/{oid}") for oid in chosen]

# 2) 各自建立訂單；要自己處理「部分成功」
results = []
for offer in latest:
    try:
        order = duffel("POST", "/air/orders", data={
            "selected_offers": [offer["id"]],
            "payments": [{"type": "balance",
                          "currency": offer["total_currency"],
                          "amount": offer["total_amount"]}],
            "passengers": passengers,   # 該 offer 對應的乘客資料
        })
        results.append(("ok", order["id"]))
    except DuffelError as e:
        results.append(("failed", str(e)))

print(results)  # 例如 [("ok", "ord_001"), ("failed", "...")]
需留意
  • 一個 slice 一張訂單：各有自己的 PNR／訂位代號，改票、退票、規則各自獨立；一邊的班表異動不會連動另一邊。
  • 必須處理部分成功：多張訂單可能只有一部分成功。
  • 分開付款：客人信用卡會有兩筆扣款（或你的餘額扣兩次），容易造成困惑。

來源：Selling split-ticket itineraries

私有票價（總覽） Search

私有票價是航空公司與代理商簽訂的特別折扣或特殊條件（例如不同的改票規則）。如果你已向航空公司備案票價，就能在搜尋時請求。有兩種：

  • 企業協議票價：在 private_fares 物件放 corporate_code、tour_code 等識別碼。
  • 休閒私有票價：在每位乘客上設 fare_type（如學生、旅行團營運商票價）。可與企業協議票價在同一次搜尋中一起請求。

來源：Accessing Private Fares

休閒私有票價 Search

針對非企業情境（學生、旅行團營運商等）。對每位適用的乘客加上 fare_type；部分涉及兒童／嬰兒的類型還可再帶 age。

python
offer_request = duffel("POST", "/air/offer_requests", data={
    "passengers": [
        {"fare_type": "student"},
        {"fare_type": "contract_bulk_child", "age": 5},
    ],
    "slices": [
        {"origin": "LHR", "destination": "JFK", "departure_date": "2026-12-24"},
        {"origin": "JFK", "destination": "LHR", "departure_date": "2026-12-30"},
    ],
})

for offer in offer_request["offers"]:
    if offer.get("private_fares"):          # 空陣列 = 沒套用私有票價
        print(offer["id"], offer["private_fares"])   # [{"type": "leisure"}]
注意各航空公司支援的 fare_type 子集合不同，你必須清楚自己向航空公司備案了哪些類型。傳入該航空公司不支援的 fare_type，會導致該航空公司沒有私有票價，甚至完全沒有 offers。若你已備案但 Duffel 尚未開放的類型，請聯絡 Duffel。

後續建立訂單的步驟與一般流程相同。

來源：Accessing Leisure Private Fares

企業協議票價 Search

航空公司直接與大型企業客戶簽訂的折扣票價，通常有更低價格、更彈性的條件。

前提必須有企業客戶與航空公司的直接合約（已完成航空公司 RFP 並有有效票價協議）。航空公司會在協議成立後提供所需代碼（如 corporate_code、tour_code）。
每筆訂位都要帶凡是在企業票價協議下訂的位，都必須傳入正確的 corporate code 與 tour code。

部分支援的航空公司

United AirlinesUAcorporate_code、tour_code
Southwest AirlinesWNcorporate_code、tour_code

顯示經停 Search

階層是 slice → segment → stop。名詞要分清楚：

名詞意義
segment（航段）一個航班；轉機時每一段都是不同航班。
stop（經停）同一個航班（同班號）中途落地，原因可能是加油、上下客，或換機型但班號不變。
layover（過站）落地後換不同班號繼續，時間從 30 分鐘到 23 小時 59 分。
stopover（停留）layover 滿 24 小時以上，是 layover 的子集合。

「直飛（non-stop）」與「有經停的直達（direct）」是旅客選 offer 的關鍵，因此值得顯示。實際呈現方式依產品而定，簡單的作法可能更好。

python
def describe_stops(offer):
    for slice_ in offer["slices"]:
        for seg in slice_["segments"]:
            flight = f'{seg["marketing_carrier"]["iata_code"]}{seg["marketing_carrier_flight_number"]}'
            print(f'{flight}: {seg["origin"]["iata_code"]} → {seg["destination"]["iata_code"]}')
            for stop in seg.get("stops") or []:
                # duration 為 ISO 8601，例如 "PT02H26M"
                print(f'   經停 {stop["airport"]["iata_code"]}，停留 {stop["duration"]}，'
                      f'再起飛時間 {stop["departing_at"]}')

stops 範例欄位：id、duration（如 PT02H26M）、departing_at，以及完整的 airport 物件（iata_code、name、time_zone、city…）。

顯示改票／退票條件 Search

offer 與 order 都有 conditions 屬性，不需呼叫新的 API，只要解讀即可。裡面有兩種條件：change_before_departure（起飛前改票）與 refund_before_departure（起飛前退票）。

航空公司怎麼定義「改」與「退」

  • 退票（refund）：拿回錢；若有罰金，會從退款中扣掉。
  • 改票（change）：保留部分價值改成別的航班，需補價差，若有罰金也要付。就算你「取消所有航班、之後再挑新的」，航空公司仍稱為「改票」。

條件的層級

  • 頂層（offer／order）：同時處理所有 slice、所有乘客的條件。
  • slice 層級：只改那一個 slice（例如只改回程日期）。
  • 沒有 slice 層級的退票條件：多個 slice 的訂單無法只退一個 slice，航空公司視為「改票」。

每個條件的欄位

欄位說明
allowed布林值，是否允許。
penalty_amount、penalty_currency罰金（已知時）；不一定與訂單幣別相同，處理改退時會依當時匯率換算。
適用範圍只涵蓋起飛前、旅客自願的改退。只要任何一段已起飛（即使旅客沒搭），或是航空公司造成的非自願異動（班表變更、取消），適用不同規則。

如何解讀

情境資料樣貌
不可退票allowed: false，罰金欄位為 null
可退票但有罰金allowed: true，罰金非零（例如 "100.00" GBP）
免費退票allowed: true，罰金 "0.00"
全部都不可改頂層 change_before_departure.allowed: false
部分可改頂層為 false，但某個 slice 的 conditions 為 true（如去程可改，罰金 25 GBP）
未知條件本身為 null。不代表不能改退或沒有費用，只代表 Duffel 不知道。
允許但罰金未知allowed: true，但 penalty_amount 與 penalty_currency 為 null
python
def describe_condition(cond):
    """把單一條件轉成給客人看的文字。"""
    if cond is None:
        return "未知（Duffel 沒有此資料）"
    if not cond["allowed"]:
        return "不允許"
    amount = cond["penalty_amount"]
    if amount is None:
        return "允許，罰金未知"
    if float(amount) == 0:
        return "允許，免手續費"
    return f'允許，罰金 {amount} {cond["penalty_currency"]}'


def describe_conditions(offer_or_order):
    cond = offer_or_order["conditions"]
    print("整張訂單改票：", describe_condition(cond["change_before_departure"]))
    print("整張訂單退票：", describe_condition(cond["refund_before_departure"]))
    for i, slice_ in enumerate(offer_or_order["slices"]):
        change = slice_["conditions"]["change_before_departure"]
        print(f"  第 {i + 1} 段改票：", describe_condition(change))

保留訂位、稍後付款 Booking

支援範圍並非所有航空公司都支援。官方建議用 Duffel Airways 或 American Airlines 的 offer 來練習。

保留（hold）訂位是先占位、之後再付款（業界稱 deferred ticketing）。作法：建立訂單不給付款，並在訂單指定的時間前付款。三步驟：找出可保留的 offer → 建立 type: "hold" 訂單 → 在期限前付款。

選位 Booking

支援範圍並非所有航空公司都支援選位。官方建議使用 American Airlines 的 offer（例如 DFW→AUS，約三個月後的日期）。同樣也可用 Ancillaries component 免自建 UI。

1. 取得座位圖

python
seat_maps = duffel("GET", "/air/seat_maps", params={"offer_id": offer_id})

if not seat_maps:
    print("此 offer 不支援選位")   # 不支援時回傳空陣列，要優雅處理

即使航空公司支援選位，某些 offer 也可能不能選（例如含其他航空公司航班）。這時 data 會是空陣列 []。

2. 解讀座位圖資料

  • cabins[]：各艙（含 cabin_class、aisles 走道數、deck、wings 機翼位置）。
  • rows[] → sections[] → elements[]。走道數 N 會讓每一列有 N+1 個 section（例如 2 條走道 → 左、中、右三區）。
  • elements[].type：seat 為座位，另有廁所、廚房（galley）、緊急出口列（exit_row）等非座位元素；需要時可渲染成空白或標記。
  • 座位的 designator 如 28B；disclosures[] 是該座位的規則文字（如「乘客須為成人」），要顯示給客人。
  • available_services 為空陣列 [] = 該座位不可選。有可用服務的座位，每位乘客各有一筆（航空公司可能對不同乘客收不同價格），含 passenger_id、total_amount（可為 0，即免費）、total_currency。
  • 列索引從 0 開始（第一列是 index 0）；wings.first_row_index／last_row_index 可用來在側邊畫機翼標記。
python
def list_free_and_paid_seats(seat_map, passenger_id):
    """回傳 {座位號: (service_id, 價格, 幣別)}，只含該乘客可選的座位。"""
    result = {}
    for cabin in seat_map["cabins"]:
        for row in cabin["rows"]:
            for section in row["sections"]:
                for el in section["elements"]:
                    if el["type"] != "seat":
                        continue
                    for svc in el["available_services"]:
                        if svc["passenger_id"] == passenger_id:
                            result[el["designator"]] = (
                                svc["id"], svc["total_amount"], svc["total_currency"]
                            )
    return result

用 services 帶入座位對應的 available_service ID，quantity 固定為 1。想為乘客 pas_… 選 28B，就用該座位上屬於此乘客的服務 ID。也可同時加行李，只要在 services 多放幾項。付款金額＝ offer 的 total_amount ＋ 所有服務的 total_amount。

                  "amount": f"{total:.2f}"}],
    "passengers": passengers,
    "services": [{"id": seat_service_id, "quantity": 1}],
})

4. 檢查結果

建單後（或之後取回訂單）可在頂層 services 看到座位服務；slices[].segments[].passengers[] 內則有 seat 屬性，內含座位號（例如 1D）。

來源：Adding Seats

取得準確價格 Booking

在付款前算出含手續費的準確價格，特別重要於兩種情況：

  1. 信用卡附加費（surcharge）：航空公司對特定卡（常見於企業卡）收取的額外費用。
  2. 幣別會依付款方式改變：航空公司可能依付款方式用不同幣別收費。

先依「Paying with customer cards」建立 card 資源。

卡片 25 分鐘過期基於安全，card 紀錄 25 分鐘後失效。失效後必須建立新的 card 資源（可代表同一張實體卡），並重新計價才能付款。

兩種流程

即時訂單保留訂單
  1. 搜尋 offers
  2. 以付款方式為 offer 計價
  3. 顯示含附加費的總額
  4. （可選）換付款方式重新計價
  5. 建立即時訂單並付款
  1. 搜尋 offers
  2. 建立 hold 訂單
  3. 以付款方式為訂單計價
  4. 顯示含附加費的總額
  5. （可選）換付款方式重新計價
  6. 完成付款

為 offer 計價

python
priced = duffel("POST", f"/air/offers/{offer_id}/actions/price", data={
    "intended_payment_methods": [
        {"type": "card", "card_id": "tcd_00009hthhsUZ8W4LxQgkjb"}
    ],
    "intended_services": [
        {"quantity": 1, "id": "ase_00009hj8USM7Ncg31cB123"}
    ],
})

card = priced["intended_payment_methods"][0]
print(card["charge_amount"], card["charge_currency"])        # 301.57 USD → 實際刷卡金額
print(card["surcharge_amount"], card["surcharge_currency"])  # 1.57 USD
  • total_amount 已包含 intended_services，但不含信用卡附加費。
  • 付款時請直接使用卡片的 charge_amount／charge_currency，不要再重複加服務或附加費。
  • 付款方式會影響幣別，一定要檢查回應中的 total_currency。
  • 對同一個 offer 多次呼叫，offer 代表最後一次的 intended_payment_methods 價格。
  • 不能在同一請求同時放 card 與 balance；airline credits 可與 card 合併使用。

選項 A：即時訂單

python
order = duffel("POST", "/air/orders", data={
    "type": "instant",
    "selected_offers": [offer_id],
    "payments": [{
        "type": "card",
        "three_d_secure_session_id": "3ds_0000AWr2XsTR1F1Vp34gh5",
        "currency": card["charge_currency"],
        "amount": card["charge_amount"],
    }],
    "services": [{"quantity": 1, "id": "ase_00009hj8USM7Ncg31cB123"}],
    "passengers": passengers,
})
必須完全一致
  • payments 必須與最後一次計價的 intended_payment_methods 完全相符；卡片付款時，three_d_secure_session_id 必須由同一張卡產生。
  • services 也必須與計價時相同。不一致會得到驗證錯誤。
  • 已付款訂單的回應不會再回傳 intended_payment_methods。

選項 B：保留訂單，之後計價與付款

python
hold = duffel("POST", "/air/orders", data={
    "type": "hold",
    "selected_offers": [offer_id],
    "services": [{"quantity": 1, "id": "ase_00009hj8USM7Ncg31cB123"}],
    "passengers": passengers,
})

# 為 hold 訂單附上／更換付款方式以取得最終價格
priced_order = duffel("POST", f"/air/orders/{hold['id']}/actions/price", data={
    "intended_payment_methods": [{"type": "card", "card_id": "tcd_00009hthhsUZ8W4LxQgkjb"}],
})
card = priced_order["intended_payment_methods"][0]

duffel("POST", "/air/payments", data={
    "order_id": hold["id"],
    "payments": [{
        "type": "card",
        "three_d_secure_session_id": "3ds_0000AWr2XsTR1F1Vp34gh5",
        "currency": card["charge_currency"],
        "amount": card["charge_amount"],
    }],
})
  • 換不同的 intended_payment_methods 再計價，價格以最後一次為準；幣別也可能改變。
  • 與 offer 不同，hold 訂單計價時不能更改 services，服務在建單時就固定。
  • 訂單 total_amount 已含服務，並可能含卡片附加費。

最佳實務

  • 票價與附加費分開顯示，付款方式選定後更新總額；說明附加費常被供應商視為不可退款。
  • 清楚顯示最終幣別。
  • 盡量在接近付款時才建立 card 資源，並實作過期重試。
  • 測試：以卡片為 Duffel Airways 的 offer／order 計價時，會回傳非零的 surcharge_amount，方便測試你的應用反應。
  • 錯誤 invalid_intended_card（HTTP 422）代表當作預定付款方式的卡片已過期；GET /air/offers/:id、GET /air/seat_maps、PATCH /air/offers/:offer_id/passengers 也會因為用最後一次付款方式重新計價而回傳此錯誤。
python
def price_with_card(offer_id, make_card):
    """卡片過期時，建立新卡並重新計價（最多重試一次）。"""
    for attempt in range(2):
        card_id = make_card()   # 自行實作：建立 card 資源並回傳 ID
        try:
            return duffel("POST", f"/air/offers/{offer_id}/actions/price", data={
                "intended_payment_methods": [{"type": "card", "card_id": card_id}],
            })
        except DuffelError as e:
            expired = any(err.get("code") == "invalid_intended_card" for err in e.errors)
            if not expired or attempt == 1:
                raise

取消訂單 Post-booking

先檢查並非所有訂單都能用 API 取消。只有訂單的 available_actions 含 "cancel" 才能；否則請在 Dashboard 的訂單頁用「Manage this order → Cancellation quote」手動申請，由 Duffel 團隊處理。

兩步驟：建立（尚未生效的）取消報價 → 確認取消。

1. 建立取消報價

python
order = duffel("GET", f"/air/orders/{order_id}")
if "cancel" not in order["available_actions"]:
    raise RuntimeError("此訂單無法透過 API 取消，請改用 Dashboard 申請取消報價")

quote = duffel("POST", "/air/order_cancellations", data={"order_id": order_id})

print(quote["id"])                                   # ore_…，下一步要用
print(quote["refund_amount"], quote["refund_currency"])
print(quote["refund_to"])                            # original_form_of_payment / airline_credits…
print(quote["expires_at"])                           # 過期後需重新取得報價
  • 依 refund_amount 決定是否繼續。
  • expires_at 已過就不能確認，需重新取得報價。
  • refund_to 表示退款去向，如 original_form_of_payment（退回原付款方式）。

2. 確認取消

python
confirmed = duffel("POST", f"/air/order_cancellations/{quote['id']}/actions/confirm")
print(confirmed["confirmed_at"])   # 有時間戳 = 訂單已取消，退款已套用

只能確認最近一次的取消報價，否則會收到 order_cancellation_stale 錯誤。被取消的訂單會在其 cancellation 屬性帶有已確認的 Order Cancellation。

航空公司點數（Airline Credits）

航空公司有時以「點數／代碼」取代現金退款，可折抵未來機票。此時 refund_to 為 airline_credits，且 airline_credits 陣列會列出明細（確認取消前 credit_code 為 null）。

python
if quote["refund_to"] == "airline_credits":
    for credit in quote["airline_credits"]:
        print(credit["passenger_id"], credit["credit_name"],
              credit["credit_amount"], credit["credit_currency"])
    # 確認取消後，credit_code 才會有值，需把代碼交給旅客
    confirmed = duffel("POST", f"/air/order_cancellations/{quote['id']}/actions/confirm")
    codes = [c["credit_code"] for c in confirmed["airline_credits"]]

測試 airline credits 可使用倫敦 Luton (LTN) → Stansted (STN) 的測試路線。

來源：Cancelling an Order

更改訂單 Post-booking

先檢查並非所有訂單都能改。訂單的 available_actions 需含 "change"。

情境：Tony 一家想把回程延後一週，改到 6/24 返回。流程四步：

  1. 建立改票請求（order change request）。
  2. 檢視可用的改票報價（order change offers）。
  3. 建立待確認的變更（pending order change）。
  4. 確認變更並付款。

0. 先取得訂單，找出要移除的 slice

order = duffel("GET", f"/air/orders/{order_id}")
assert "change" in order["available_actions"]

slice_to_remove_id = order["slices"][1]["id"]

提供要移除的 slice 清單，以及要新增的搜尋條件。

change_request = duffel("POST", "/air/order_change_requests", data={
    "order_id": order_id,
    "slices": {
        "remove": [{"slice_id": slice_to_remove_id}],
        "add": [{
            "origin": "ATL",
            "destination": "SWF",
            "departure_date": "2026-06-24",
            "cabin_class": "business",
        }],
    },
})
change_request_id = change_request["id"]   # ocr_…

2. 檢視可用的改票報價

python
change_request = duffel("GET", f"/air/order_change_requests/{change_request_id}")

for o in change_request["order_change_offers"]:
    print(o["id"],
          "價差", o["change_total_amount"],      # 新舊航班價差，可正可負
          "罰金", o["penalty_total_amount"],     # 航空公司收的手續費
          o["change_total_currency"])

每個 order_change_offers 都含要新增／移除的 slice 細節，以及 change_total_amount（價差，新航班可能更貴或更便宜）與 penalty_total_amount（航空公司罰金）。

3. 建立待確認的變更

python
order_change = duffel("POST", "/air/order_changes", data={
    "selected_order_change_offer": chosen_offer_id,

order_change = duffel("GET", f"/air/order_changes/{order_change['id']}")
注意待確認變更的價格會變動，請讓客戶看過最終價格再確認。同樣必須顯示 Duffel 規定的法律告知。

4. 確認變更

    "payment": {
        "type": "balance",
        "currency": order_change["change_total_currency"],
        "amount": order_change["change_total_amount"],
    },
})

確認後，原訂單會顯示新的 slices，並帶有航空公司的 booking_reference。之後隨時可用訂單 id 取回。

備註官方範例的 confirm 付款金額寫死 "50.00" GBP；實務上應使用最新 order change 的應付金額。上方範例以 change_total_* 示意，欄位名稱以你取得的實際回應為準。

訂位後加購行李 Post-booking

支援範圍訂位後加購尚未支援所有航空公司，官方建議用 easyJet 的訂單練習。另外，只能對原訂單沒有包含行李的情況加購。

1. 列出訂單的可加購服務

python
services = duffel("GET", f"/air/orders/{order_id}/available_services")

for s in services:
    print(s["id"], s["type"], s["metadata"],
          s["total_amount"], s["total_currency"],
          s["segment_ids"], s["passenger_ids"])

2. 付款並加購

對 /air/orders/:id/services 送出 add_services（每項含服務 ID 與數量）及 payment。金額＝ Σ（單價 × 數量）。例如服務 A 數量 2、單價 10 GBP，付款為 20 GBP。

python
from decimal import Decimal

wanted = [(service_id_1, 2), (service_id_2, 1)]
price_of = {s["id"]: Decimal(s["total_amount"]) for s in services}
total = sum(price_of[sid] * qty for sid, qty in wanted)

order = duffel("POST", f"/air/orders/{order_id}/services", data={
    "payment": {
        "type": "balance",
        "currency": services[0]["total_currency"],
        "amount": f"{total:.2f}",
    },
    "add_services": [{"id": sid, "quantity": qty} for sid, qty in wanted],
})

3. 查看訂單上的服務

python
order = duffel("GET", f"/air/orders/{order_id}")
print(order["services"])   # quantity 取代 maximum_quantity

與訂位時加購相同：加購的行李只在 services 內，不在 slices[].segments[].passengers[].baggages[]，要看完整行李需合併兩者。

完整流程腳本

把「搜尋 → 取得最新 offer → 看座位圖 → 建立訂單 → 取消報價」串成一支可執行的範例。請使用測試 token，並依你想測的航空公司調整路線與日期（Duffel Airways 為測試用航空公司）。

flow.py
from datetime import date, timedelta
from decimal import Decimal

# 假設 duffel() 與 DuffelError 已定義（見「環境與共用 helper」）

depart = (date.today() + timedelta(days=90)).isoformat()

# 1) 搜尋
req = duffel("POST", "/air/offer_requests", params={"return_offers": "true"}, data={
    "slices": [{"origin": "LHR", "destination": "LGW", "departure_date": depart}],
    "passengers": [{"type": "adult"}],
    "cabin_class": "economy",
    "max_connections": 0,
})
cheapest = min(req["offers"], key=lambda o: Decimal(o["total_amount"]))
passenger_id = req["passengers"][0]["id"]

# 2) 取得最新 offer（含可加購服務）
offer = duffel("GET", f"/air/offers/{cheapest['id']}",
               params={"return_available_services": "true"})
print("總價", offer["total_amount"], offer["total_currency"])

# 3) 看看能不能選位
seat_maps = duffel("GET", "/air/seat_maps", params={"offer_id": offer["id"]})
print("座位圖數量：", len(seat_maps))

# 4) 建立訂單
order = duffel("POST", "/air/orders", data={
    "selected_offers": [offer["id"]],
    "payments": [{"type": "balance",
                  "currency": offer["total_currency"],
                  "amount": offer["total_amount"]}],
    "passengers": [{
        "id": passenger_id,
        "title": "mr", "gender": "m",
        "given_name": "Tony", "family_name": "Stark",
        "born_on": "1980-07-24",
        "email": "tony@example.com", "phone_number": "+442080160508",
    }],
})
print("訂單", order["id"], "訂位代號", order["booking_reference"])

# 5) 取消報價（先看退多少，再決定是否確認）
if "cancel" in order["available_actions"]:
    quote = duffel("POST", "/air/order_cancellations", data={"order_id": order["id"]})
    print("退款", quote["refund_amount"], quote["refund_currency"], "→", quote["refund_to"])

錯誤處理與檢查表

指南中出現的錯誤碼

錯誤出現情境處理
price_changed用過時價格支付 hold 訂單重新 GET /air/orders/:id 後用新價格付款
schedule_changedhold 訂單在建單與付款之間被航空公司改班表重新確認行程，必要時重訂
order_cancellation_stale確認的不是最新一次取消報價重新建立取消報價再確認
invalid_intended_card（422）預定付款的卡片已過期（25 分鐘）建立新 card 資源並重新計價

實作檢查表

  • token 放環境變數；開發階段使用測試 token。
  • 選定 offer 後，先 GET /air/offers/:id 取最新價格，再收乘客資料與付款。
  • 建單的付款金額＝ offer 總額＋所有加購服務（座位、行李）。
  • 使用卡片付款時，payments 與 services 必須與最後一次計價一致。
  • 執行改票、取消前，先檢查訂單的 available_actions。
  • 在 UI 顯示改退條件時，null 代表「未知」而不是「不允許」。
  • 顯示 Duffel 規定的法律告知；填乘客本人的 email。
  • 座位圖、加購服務可能為空——要有「不支援」的處理路徑。
  • 分開購票、hold 訂單等需處理部分成功與逾時。
